# v20 and v21: four candidate checkpoints

Four exploratory checkpoints built from the published v19 and from public bases, with the
code and configs to train, calibrate, evaluate and serve each. None of them is a published
release, and none was preregistered: they are candidates. Every default of the package is
unchanged; each change they rely on is opt-in.

| Name | Base | Starts from | Configs | Answers over |
| --- | --- | --- | --- | --- |
| `strands-decider-2B-hobson-v20` | Qwen3.5-2B-Base | v19 | [configs/experiments/strands-decider-2B-hobson-v20*.yaml](../configs/experiments/) | text |
| `strands-decider-2B-hobson-v20-vl` | Qwen3.5-2B-Base | v20 | [configs/vision/strands-decider-2B-hobson-v20-vl*.yaml](../configs/vision/) | text and images |
| `strands-decider-2.5B-minicpm-v21` | MiniCPM5-2B | the raw base | [configs/experiments/strands-decider-2.5B-minicpm-v21*.yaml](../configs/experiments/) | text |
| `strands-decider-2.5B-minicpm-v21-vl` | MiniCPM5-2B + SigLIP2 so400m | v21 | [configs/align/](../configs/align/), [configs/vision/strands-decider-2.5B-minicpm-v21-vl*.yaml](../configs/vision/) | text and images |

- **v20** continues v19 for one full epoch (3,738 steps) on v19's own training data with two
  changes aimed at yes/no answers left near 0.5: Qwen3.5-27B's distributions on the yes/no
  rows, kept where they agree with gold (`training/recipe.sh teacher_yn`,
  `src/strands_decider/data/teacher_yn.py`), and no frozen-KL anchor on yes/no rows
  (`kl_frozen_skip_kinds`). Three seeds from one initialisation (`init_seed`), then their
  weight average (`strands-decider soup`), which is the model.
- **v21** is the same recipe trained from the raw MiniCPM5-2B base (a Llama decoder; 2.5B
  parameters with the readout) instead of continuing v19. MiniCPM5 was chosen by a base
  bake-off ([below](#the-base-bake-off)) whose decision rule was fixed before any score.
- **v20-vl** continues the v20 soup on ~38,000 questions over images
  ([data/image/README.md](../data/image/README.md)), with image-removed copies, no frozen-KL
  anchor on yes/no rows and 3,000 replayed text rows that train toward their 27B-teacher
  targets, so that one checkpoint keeps v20's text behaviour and reads images with Qwen3.5's
  own vision tower.
- **v21-vl** gives the v21 soup eyes: a frozen SigLIP2 so400m encoder and a projector trained
  first alone on COCO captions, then with the adapter and head on the same image recipe
  ([vision.md](vision.md#a-torso-without-a-vision-tower-grafted-eyes-minicpm5)).

**Results.** Every number (per seed, means, paired 95% intervals against v19 and between
candidates, the local measures below) and every per-item result, log, data hash and
run summary is in the results release: https://github.com/Vivek0712/strands-decider/blob/b63bc26de24a935a4925ed96616954f82daf1f80/research/v21/RESULTS.md. Weights: https://vision-decider-643603452951-us-east-1.s3.us-east-1.amazonaws.com/weights/<name>.tar (checksums: https://vision-decider-643603452951-us-east-1.s3.us-east-1.amazonaws.com/weights/weights_SHA256SUMS.txt).
The published `strands-decider-2B-hobson-v20-balanced` package is seed 0 of the
`strands-decider-2B-hobson-v20-vl` configs, and `strands-decider-2.5B-minicpm-v21-vl` is seed 1 of its configs;
`strands-decider-2B-hobson-v20` is the soup of three seeds and `strands-decider-2.5B-minicpm-v21` is seed 0.
Read every JevBench number here as a **local proxy** of v1.5 scoring on the 231 public v1
tasks, never as a board score.

Paths are relative to the repository root unless they are links.

## Setup

Linux with NVIDIA GPUs; the recorded runs used one H200 per training run, Python 3.11,
torch 2.7.1 and transformers 5.18.0. Every model download is pinned to a revision in the
configs and modules (`base_revision`, `init_revision`, `encoder_revision`,
`data/teacher_yn.py`'s `REVISION`).

```bash
pip install -e ".[train,vision,cuda]"
pip install matplotlib imagehash pandas pyarrow      # the -vl models: image data, dedupe, image evaluation
pip install vllm                                     # optional: TEACHER_ENGINE=vllm
hf download StrandsAgents/strands-decider-2B-hobson-v19 \
  --revision bb282d786bc251fd4e3068de3ada9ddbb38127cd --local-dir checkpoints/v19
training/recipe.sh build fetch multistep generated adequacy teacher_yn
```

`teacher_yn` labels the 54,857 yes/no rows with Qwen3.5-27B in bf16 (an 80 GB GPU, about
30 GPU-minutes on an H100) and writes `data/teacher_yn_qwen35-27b.jsonl`. The labels are not
committed; [data/README.md](../data/README.md) gives the hashes of the files the recorded runs
trained on. A relabel batches rows differently, so its bf16 probabilities need not match
byte for byte.

## Calibration

Every text checkpoint is calibrated in two steps before serving. The first is the usual
one, on `data/holdout_v5_norule.jsonl`. The second refits only the choice and score
temperatures, by NLL, on held-out rows of the training families (v19's own evaluation
splits, plus the held-out tasks for score rows), and keeps the yes/no temperature the first
step fitted:

```bash
calibrate() {  # calibrate CKPT
  strands-decider calibrate "$1" --data data/holdout_v5_norule.jsonl
  strands-decider calibrate "$1" --kinds choice,score --objective nll --limit 900 \
    --data data/adequacy_hs2_eval.jsonl --data data/synthetic/adequacy_gen_eval.jsonl \
    --data data/synthetic/generated_v16_eval.jsonl --data data/synthetic/generated_v18_eval.jsonl \
    --data data/multistep_v14_eval.jsonl --data data/holdout_v5_norule.jsonl
}
```

Why the second step: `data/holdout_v5_norule.jsonl` rebuilds today with a different hash
from the one in `data/SHA256SUMS` (an upstream held-out dataset has changed), and on it the
first step gave every MiniCPM5 checkpoint a score temperature of 3.7-4.6, which flattens
score answers. Refitting every kind by NLL instead would also soften the yes/no
temperature, pulling decisive yes/no answers back into the 0.2-0.8 band that v1.5 counts
as wrong; `--kinds` refits only the listed kinds. `--limit` caps each file's calibration
half, so the multi-step and held-out files do not crowd out the small evaluation splits.
The recorded temperatures came from an equivalent exploratory fit (a half drawn by row
hash, the multi-step file capped at 900 rows and the held-out file at 1,800 before
halving); this command draws a similar but not identical half, so its temperatures need
not match the recorded ones (in the results release) exactly.

## Train

### strands-decider-2B-hobson-v20

```bash
for s in "" -seed1 -seed2; do
  strands-decider train --config configs/experiments/strands-decider-2B-hobson-v20$s.yaml
done
strands-decider soup checkpoints/strands-decider-2B-hobson-v20-s{0,1,2} \
  --out checkpoints/strands-decider-2B-hobson-v20
calibrate checkpoints/strands-decider-2B-hobson-v20
```

Each seed takes about 2 h on one H200. The soup resets the calibration (the average
of calibrated models is not calibrated), so it is calibrated after averaging; `soup.json`
records its inputs, the method and the library versions.

### strands-decider-2.5B-minicpm-v21

```bash
for s in "" -seed1 -seed2; do
  strands-decider train --config configs/experiments/strands-decider-2.5B-minicpm-v21$s.yaml
done
strands-decider soup checkpoints/strands-decider-2.5B-minicpm-v21-s{0,1,2} \
  --out checkpoints/strands-decider-2.5B-minicpm-v21
calibrate checkpoints/strands-decider-2.5B-minicpm-v21
```

Each seed takes about 2 h 30 min on one H200. MiniCPM5-2B is downloaded at its pinned revision (`base_revision` in the config); its
untied output head is read once from the base's safetensors for the frozen-KL readout.

### strands-decider-2B-hobson-v20-vl

```bash
training/recipe_images.sh fetch build dedupe
python -m strands_decider.data.teacher_yn replay --teacher data/teacher_yn_qwen35-27b.jsonl \
  --n-yes-no 2000 --n-other 1000 --out data/replay_teacher_yn.jsonl
for s in "" -seed1 -seed2; do
  CONFIG=configs/vision/strands-decider-2B-hobson-v20-vl$s.yaml training/recipe_images.sh train eval
done
```

It starts from the calibrated v20 soup (`init_from` in the config) and keeps its text
temperatures. `replay` draws 3,000 of v20's training rows (2,000 yes/no) with their teacher
distributions; the recorded runs used a file built the same way whose exact draw was not
kept, so a rebuild replays different rows.
`eval` fits image temperatures on NaturalBench groups 300-599; to serve with them, write
them into the checkpoint:

```bash
python evaluation/vision/temps.py fit --run reports/strands-decider-2B-hobson-v20-vl-s0/cal \
  --out reports/strands-decider-2B-hobson-v20-vl-s0/image_temps.json \
  --checkpoint checkpoints/strands-decider-2B-hobson-v20-vl-s0
```

### strands-decider-2.5B-minicpm-v21-vl

```bash
training/recipe_images.sh fetch build dedupe          # stage 2's image rows, as for v20-vl
training/recipe_minicpm_vision.sh fetch build dedupe align train eval
for s in 0 1 2; do calibrate checkpoints/strands-decider-2.5B-minicpm-v21-vl-s$s; done
```

`align` trains the projector alone on 80,000 COCO train2014 captions through the frozen
MiniCPM5-2B (`configs/align/strands-decider-2.5B-minicpm-v21-vl.yaml`, about 12 minutes on
an H200); `train` runs stage 2 from the v21 soup for each seed. Stage 2 starts from the v21
soup's temperatures; the calibration above refits the text ones on the grafted checkpoint
(`strands-decider calibrate` reads it as the text model `serve --vision` answers text with),
and image temperatures are written as for v20-vl.

## Serve

```bash
strands-decider serve checkpoints/strands-decider-2B-hobson-v20 --port 8000
strands-decider serve checkpoints/strands-decider-2.5B-minicpm-v21 --port 8000
strands-decider serve checkpoints/strands-decider-2B-hobson-v20-vl-s0 --vision \
  --image-long-side 0 --image-max-pixels 400000 --port 8000
strands-decider serve checkpoints/strands-decider-2.5B-minicpm-v21-vl-s0 --vision \
  --image-long-side 0 --image-max-pixels 400000 --port 8000
```

The -vl models are trained as three seeds, not averaged; the results release names the seed
published under each name. The image-trained checkpoints were trained at a budget of 400,000 pixels per image, which
`--image-long-side 0 --image-max-pixels 400000` reproduces (`serve --vision` otherwise caps
the longer side at 448 px). A grafted checkpoint is recognised by its `projector_config.json`.
Text requests to a `--vision` server take the text path. Downloaded weights
(https://vision-decider-643603452951-us-east-1.s3.us-east-1.amazonaws.com/weights/<name>.tar) serve the same way from their local directory.

## Evaluate

### JevBench v1 public, scored with the local v1.5 proxy

```bash
for m in strands-decider-2B-hobson-v20 strands-decider-2.5B-minicpm-v21; do
  PY=$(which python) GPU=0 evaluation/jevbench/jevbench.sh checkpoints/$m reports/jevbench/$m
done
for m in strands-decider-2B-hobson-v20-vl strands-decider-2.5B-minicpm-v21-vl; do
  PY=$(which python) GPU=0 SERVE_ARGS=--vision evaluation/jevbench/jevbench.sh checkpoints/$m-s0 reports/jevbench/$m-s0
done
PY=$(which python) GPU=0 evaluation/jevbench/jevbench.sh checkpoints/v19 reports/jevbench/v19
python evaluation/jevbench/v15_proxy.py reports/jevbench/strands-decider-2B-hobson-v20 --vs reports/jevbench/v19
```

[`v15_proxy.py`](../evaluation/jevbench/v15_proxy.py) applies v1.5's published rules to the
public results: a yes/no answer with 0.2 < P(yes) < 0.8 counts wrong, yes/no and choice
credit is chance-corrected, and score tasks are graded by the expected level of the
returned distribution (100 * (1 - mean nMAE / mean nMAE of a random level)), reading each
task's gold level from the run's `all.jsonl`. It leaves out v1.5's tier weights and sealed
half: a local proxy for ranking runs against each other, not the board's score. Given
several runs before `--vs` (seeds), it reports their mean difference from the baseline with
a paired bootstrap 95% interval over the 231 tasks.

### Unseen task families

```bash
python evaluation/unseen/build.py --out data/unseen.jsonl
python evaluation/unseen/run.py --rows data/unseen.jsonl --checkpoint checkpoints/strands-decider-2B-hobson-v20 \
  --out reports/unseen/strands-decider-2B-hobson-v20
python evaluation/unseen/run.py --rows data/unseen.jsonl --checkpoint checkpoints/v19 --out reports/unseen/v19
python evaluation/unseen/score.py reports/unseen/strands-decider-2B-hobson-v20 --vs reports/unseen/v19
```

1,050 questions from five public datasets no training mixture contains (StrategyQA,
RuleTaker depth 5, CommonsenseQA, ARC-Challenge, STS-B), pinned to dataset revisions,
graded with the same v1.5 rules: how a checkpoint does on question families it never saw.
Add `--vision` to `run.py` for the -vl checkpoints. Other deciders run through their own
published code or HTTP API behind an adapter: [evaluation/unseen/README.md](../evaluation/unseen/README.md).

### Images (the -vl models)

`training/recipe_images.sh eval` and `training/recipe_minicpm_vision.sh eval` run the image
evaluation of [vision.md](vision.md#how-well-it-does) at the 400,000-pixel budget
(NaturalBench, POPE, and with `IJB_JSONL` the 60 rebuildable Image JevBench preview items,
each with the image removed too), the fitted image temperatures, and the 899-row text check
(`evaluation/vision/text_check.py`). Compare seeds with a baseline:

```bash
CKPT=StrandsAgents/strands-decider-2B-hobson-v19 OUT=reports/v19-400k training/recipe_images.sh eval
python evaluation/vision/compare.py reports/strands-decider-2B-hobson-v20-vl-s{0,1,2}/eval --vs reports/v19-400k/eval
```

## The base bake-off

v21's base was chosen by training one recipe from three raw bases on the same data, budget
(2,400 steps) and seed: [configs/experiments/bakeoff/](../configs/experiments/bakeoff/)
(Qwen3.5-2B-Base at two seeds, MiniCPM5-2B, Gemma 4 E2B; identical but for the base, its revision
and the LoRA target names, which `tests/test_configs.py` holds). The rule, fixed before any
score: the primary measure is the v1.5 proxy Intelligence on JevBench v1 public; a non-Qwen
base wins only if it is above the higher of the two Qwen seeds (their spread is the noise
floor); between two that clear it, the higher proxy wins, and within 1.0 point the lower
Brier, then the faster p50 latency.

```bash
for b in qwen35-2b qwen35-2b-seed1 minicpm5-2b gemma4-e2b; do
  strands-decider train --config configs/experiments/bakeoff/$b.yaml
  strands-decider calibrate checkpoints/bakeoff-$b --data data/holdout_v5_norule.jsonl
  PY=$(which python) GPU=0 evaluation/jevbench/jevbench.sh checkpoints/bakeoff-$b reports/jevbench/bakeoff-$b
  python evaluation/jevbench/v15_proxy.py reports/jevbench/bakeoff-$b
done
```

The bake-off arms were calibrated with the first step only. A Gemma 4
E2B text checkpoint serves and trains on images too ([vision.md](vision.md#gemma-4-e2b-checkpoints),
`configs/vision/gemma4-e2b-images*.yaml`).

## Limits

- Exploratory: three seeds per arm, local runs on public data, arms chosen after looking at
  earlier results. A published checkpoint needs a preregistered, confirmatory run.
- The JevBench proxy and the unseen-family score are local measures. The unseen set is one
  draw of 1,050 rows: differences of a few points are within noise; read the intervals.
- The 60 Image JevBench preview items are rebuilt from their sources, not the sealed set.
- The VQAv2 and COCO downloads have no revision; [data/image/README.md](../data/image/README.md)
  records the hashes of the rows the recorded runs trained on.
